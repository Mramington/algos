# C. Бронирование

## Условие

Дана база данных PostgreSQL с таблицей бронирований `bookings`. Необходимо
реализовать **HTTP-сервис** для управления бронированиями мест.

## Схема базы данных

```sql
CREATE TABLE bookings (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL,
    place_id INTEGER NOT NULL,
    time_from TIMESTAMP NOT NULL,
    time_to TIMESTAMP NOT NULL
);
```

## Запуск

Зависит от выбранного языка (см. условие в созданном репозитории). Во всех
случаях собранный бинарь принимает аргумент командной строки:

```
--port <port>
```

где `port` — порт, на котором разворачивается сервис.

## API

Сервис реализует следующие эндпоинты и возвращает корректные HTTP-коды.

### `GET /ping`

Health check. Возвращает `HTTP 200` с телом:

```json
{"status":"ok"}
```

### `POST /book`

Создание нового бронирования.

**Query-параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `place_id` | integer | ID места |
| `user_id` | integer | ID пользователя |
| `from` | string | начало бронирования в формате RFC3339 (напр. `2024-01-01T10:00:00Z`) |
| `to` | string | конец бронирования в формате RFC3339 |

**Ответ:**
* `HTTP 200` — бронирование успешно создано;
* `HTTP 409` — конфликт: запрашиваемый интервал пересекается с существующим
  бронированием для этого места.

Два полуинтервала `[from1, to1)` и `[from2, to2)` (при `from1 < to1`) считаются
пересекающимися, если `from2 < to1` (и симметрично `from1 < to2`).

### `GET /booklist`

Получение списка бронирований.

**Query-параметры (ровно один из двух):**

| Параметр | Тип | Описание |
|---|---|---|
| `user_id` | integer | вернуть все бронирования пользователя |
| `place_id` | integer | вернуть все бронирования места |

**Ответ** `HTTP 200` с телом:

```json
{
  "bookings": [
    {
      "id": 1,
      "user_id": 10,
      "place_id": 5,
      "from": "2024-01-01T10:00:00Z",
      "to": "2024-01-01T12:00:00Z"
    }
  ]
}
```

Бронирования должны быть отсортированы по `(from, id)` по возрастанию.

## Подключение к базе данных

Параметры подключения передаются через переменные окружения:

| Переменная | По умолчанию |
|---|---|
| `DB_HOST` | `localhost` |
| `DB_PORT` | `5432` |
| `DB_USER` | `postgres` |
| `DB_PASSWORD` | `postgres` |
| `DB_NAME` | `contest` |

## Требования

* Сервис должен корректно обрабатывать **последовательные блокирующие
  запросы** — тестирующая система посылает следующий запрос только после
  получения ответа на предыдущий.

## Замечания по реализации

* Проверку пересечения интервалов для `POST /book` удобно выполнять одним
  SQL-запросом к строкам с тем же `place_id`:
  условие пересечения полуинтервалов — `new_from < time_to AND time_from <
  new_to`. Если такая строка существует — вернуть `409`, иначе вставить новую
  и вернуть `200`.
* Времена принимаются и возвращаются в формате RFC3339 (UTC, суффикс `Z`).
* Для `GET /booklist` фильтрация идёт по тому из параметров (`user_id` или
  `place_id`), который передан, с `ORDER BY time_from, id`.

## Запуск (пример)

```bash
./service --port 8080
```
