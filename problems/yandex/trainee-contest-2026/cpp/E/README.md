# E. Оптимальные деревья поиска

## Условие

Есть упорядоченный массив из `N` различных элементов. На вход алгоритму
бинарного поиска передаётся некоторое число, которое **гарантированно**
равно какому-то элементу массива. Элемент с номером `i` (`1 ≤ i ≤ N`)
запрашивается с вероятностью `wᵢ / S`, где `S` — сумма всех весов `wᵢ`.

Алгоритм поиска работает так: он выбирает индекс `i`, сравнивает искомое
число с элементом `arr[i]` и в зависимости от результата (равно / меньше /
больше) либо завершается, либо рекурсивно продолжает поиск в одной из частей
массива по такой же схеме.

Нужно построить алгоритм (по сути — **бинарное дерево поиска**), чтобы
**математическое ожидание числа итераций было минимальным**. Если оптимальных
алгоритмов несколько, требуется вывести их все.

## Ограничения

| Параметр | Значение |
|---|---|
| `1 ≤ N ≤ 800` | длина массива |
| `1 ≤ wᵢ ≤ 1000` | веса элементов |
| `K ≤ 1000` | число оптимальных алгоритмов (гарантируется во всех тестах) |
| Время | 3.5 с (40 с для CPython, 15 с для PyPy) |
| Память | 512 МБ |

## Формат ввода

```
N
w₁ w₂ … w_N
```

* Первая строка — число `N`.
* Вторая строка — `N` целых весов.

## Формат вывода

В первой строке — `K`, число оптимальных алгоритмов.

Далее `K` строк, по `N` чисел в каждой — описание одного алгоритма (обход
дерева). Описание задаётся рекурсивно:

1. Первое число — индекс `i` корня (1-индексация) — элемент, который
   проверяется первым.
2. Затем идут `i − 1` чисел — описание левого поддерева (элементы `1 … i−1`),
   рекурсивно в том же формате (что делать, если искомое число **меньше**).
3. Затем идут `N − i` чисел — описание правого поддерева (элементы `i+1 … N`),
   рекурсивно в том же формате (что делать, если искомое число **больше**).

Алгоритмы можно выводить в любом порядке.

### Разбор формата на примере

Строка `3 1 2 5 4 6` описывает алгоритм:

* сначала проверяется 3-й элемент (корень);
* если меньше — описание левого поддерева `1 2`: проверяется 1-й, при неудаче — 2-й;
* если больше — описание правого поддерева `5 4 6`: проверяется 5-й, затем 4-й или 6-й.

При весах `1 2 3 4 5 6` ожидание числа итераций равно

```
(1·3 + 2·(1+5) + 3·(2+4+6)) / (1+2+3+4+5+6)
```

(корень — 1 итерация, элементы 1 и 5 — по 2 итерации, элементы 2, 4 и 6 — по 3).

## Примеры

**Пример 1**

```
Ввод            Вывод
3               3
2 1 2           1 3 2
                2 1 3
                3 1 2
```

При весах `2 1 2` корнем может быть любой из трёх элементов — все три дерева
дают одинаковое минимальное ожидание, поэтому выводятся все три.

**Пример 2**

```
Ввод            Вывод
3               2
1 2 3           2 1 3
                3 2 1
```

## Идея решения

Это классическая задача **Optimal Binary Search Tree** (поиск без «промахов»:
искомый ключ всегда есть в массиве).

### Стоимость дерева

Глубина узла (число сравнений до него) для корня равна 1. Минимизируем
суммарную взвешенную глубину `Σ wᵢ · depthᵢ`. Удобная формула:

> Стоимость поддерева на отрезке `[i, j]` равна сумме оптимальных стоимостей
> левого и правого поддеревьев плюс сумма весов всего отрезка `W(i, j)`.
> Прибавление `W(i, j)` отражает то, что выбор корня добавляет ровно одну
> итерацию каждому ключу отрезка.

### Динамическое программирование

`cost[i][j]` — минимальная стоимость BST на ключах `i … j`:

```
cost[i][j] = W(i, j) + min over r in [i..j] of ( cost[i][r-1] + cost[r+1][j] )
```

где `W(i, j)` берётся через префиксные суммы за O(1).

Наивно это `O(N³)`. Чтобы уложиться в `N = 800`, применяется оптимизация
**Кнута–Яо** (свойство монотонности оптимального корня
`root[i][j-1] ≤ root[i][j] ≤ root[i+1][j]`), сводящая сложность к `O(N²)`.

### Восстановление всех оптимальных деревьев

Дополнительно храним для каждого отрезка `[i, j]` **множество всех корней `r`**,
дающих минимум. Затем рекурсивно перебираем все комбинации корней левого и
правого поддеревьев, формируя каждую строку обхода в требуемом формате (корень,
затем рекурсивно левое, затем правое поддерево). Поскольку гарантируется
`K ≤ 1000`, явный перебор всех вариантов укладывается в ограничения.

## Сложность

| | |
|---|---|
| Время | `O(N²)` на подсчёт стоимостей + `O(K · N)` на вывод |
| Память | `O(N²)` |
