# Решение MCMF через SPFA

## Общая идея — Successive Shortest Paths (SSP)

Жадная стратегия: всегда пускай следующую единицу потока по самому дешёвому из доступных путей. Это корректно благодаря выпуклости стоимости потока.

```
пока существует путь s→t в остаточной сети:
    найти кратчайший (по стоимости) путь s→t через SPFA
    пустить по нему максимально возможный поток
    обновить остаточную сеть
```

Каждая итерация насыщает хотя бы одно ребро, поэтому алгоритм гарантированно завершается.

---

## Роль SPFA

На каждой итерации нужно найти путь **минимальной стоимости** в остаточной сети. Остаточная сеть всегда содержит обратные рёбра с весом `-w` — отрицательные рёбра. Поэтому Dijkstra без дополнительных преобразований неприменима, и используется SPFA.

SPFA релаксирует рёбра с двумя отличиями от обычного SSSP:

- Рёбра с нулевой остаточной пропускной способностью (`cap - flow = 0`) не рассматриваются — по ним нельзя пустить поток
- Дополнительно запоминается не только предыдущая вершина, но и **индекс ребра** — чтобы потом обновить `flow` на прямом и обратном ребре

---

## Увеличение потока вдоль пути

После того как SPFA нашёл кратчайший путь, нужно пустить по нему поток:

1. Пройти по пути от `t` до `s` через `prev`, найти минимальную остаточную пропускную способность `push = min(cap - flow)`
2. Пройти по пути снова, обновить поток: `flow += push` на прямых рёбрах, `flow -= push` на обратных
3. Добавить к суммарной стоимости `push · d[t]`, где `d[t]` — стоимость найденного пути

Обратное ребро для ребра с индексом `i` имеет индекс `i ^ 1` — это работает если рёбра добавляются парами (прямое с чётным индексом, обратное с нечётным).

---

## Структура данных

Каждое ребро хранит:
- `to` — вершина назначения
- `w` — стоимость единицы потока
- `cap` — пропускная способность
- `flow` — текущий поток

Остаточная пропускная способность: `cap - flow`.

Обратное ребро добавляется при добавлении каждого прямого ребра: `cap = 0`, `w = -w`.

---

## Сложность

Каждая итерация SSP: SPFA за O(V · E) в худшем случае. Итераций не более `f*` (величина максимального потока).

Итого: **O(V · E · f\*)**.

На практике работает значительно быстрее из-за эвристической природы SPFA.

---

## Сравнение с Dijkstra + потенциалы

| | SSP + SPFA | SSP + Dijkstra + потенциалы |
|---|---|---|
| Сложность итерации | O(V · E) худший | O(E log V) |
| Реализация | Проще | Сложнее |
| Надёжность | Можно взломать тестами | Стабильна |
| Отрицательные рёбра | Работает напрямую | Нужна инициализация потенциалов |

Для соревнований с жёсткими тестами предпочтительнее Dijkstra с потенциалами. SPFA подходит когда граф небольшой или нужно быстро написать решение.
